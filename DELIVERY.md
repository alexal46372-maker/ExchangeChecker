# DELIVERY.md — поставка Exchange Checker заказчику

Check ID: **CHK-DELIV-01**

## Принцип

Заказчик получает **только готовый zip с бинарниками**. Исходный код, инструкции по сборке и среда разработки заказчику **не передаются**. Сборка и упаковка выполняются **только в среде нейронки (AI)**; заказчик **никогда** не собирает продукт сам.

## Содержимое zip

Поставка — один архив `ExchangeChecker-<version>-windows-amd64.zip` (собирает `tools/mkzip`, детерминированно), внутри ровно одна запись:

| Файл | Назначение |
|------|------------|
| `ExchangeCheckerSetup.exe` | Инсталлятор (мастер и тихий режим). Служба, трей и деинсталлятор вложены внутрь, сжаты gzip; распаковываются при установке. |

Итоговые артефакты сборки (имена рабочих exe):

| Артефакт | Компонент |
|----------|-----------|
| `ExchangeCheckerSvc.exe` | Служба Windows |
| `ExchangeCheckerTray.exe` | Трей (UI) |
| `ExchangeCheckerSetup.exe` | Инсталлятор |
| `ExchangeCheckerUninstall.exe` | Деинсталлятор: отдельная маленькая сборка того же кода без вложенных exe, кладётся инсталлятором в папку установки (Uninstall-ключ); в zip не входит |

Папка установки (по умолчанию `%ProgramFiles%\ExchangeChecker`): `ExchangeCheckerSvc.exe`, `ExchangeCheckerTray.exe`, `ExchangeCheckerUninstall.exe`; DACL всегда защищённый — SYSTEM и Administrators полный доступ, Users чтение и выполнение. Удаление: если exe деинсталлятора занят, он удаляется при перезагрузке (`MoveFileExW` с отложенным удалением), код выхода 3010.

Версия: релиз — тег `vX.Y.Z` (VERSIONINFO и «Программы и компоненты» показывают `X.Y.Z`), сборки CI — `0.0.0-ci.<номер запуска>`. Издатель (Publisher / CompanyName / LegalCopyright) не указывается. **Код не подписан** (v1): возможны предупреждение SmartScreen и ложные срабатывания антивирусов.

В zip для заказчика **не** включаются: исходники, `go.mod`/`go.sum`, тесты, `node_modules`, скрипты сборки, документация разработчика (кроме краткого README для пользователя при необходимости).

## Ключи командной строки

Установка: `ExchangeCheckerSetup.exe [/S] [/DIR=<папка>] [/NOSTART] [/NOSHORTCUT] [/LOG=<файл>] [/ALLOWDOWNGRADE] [/LANG=ru|en]`.
Удаление: `ExchangeCheckerUninstall.exe /uninstall [/S] [/PURGEDATA] [/LOG=<файл>] [/LANG=ru|en]` (или «Программы и компоненты»).

| Ключ | Смысл |
|------|-------|
| `/S` | Тихий режим: без окон и вопросов, трей после установки не запускается |
| `/DIR=` | Папка установки (по умолчанию `%ProgramFiles%\ExchangeChecker`); при обновлении игнорируется — берётся установленная |
| `/NOSTART` | Не запускать службу и не ставить автозапуск (только новая установка; при обновлении состояние службы сохраняется) |
| `/NOSHORTCUT` | Не создавать ярлык в меню «Пуск» (`Exchange Checker\Exchange Checker.lnk`) |
| `/LOG=` | Файл журнала установки (по умолчанию в `%TEMP%`) |
| `/ALLOWDOWNGRADE` | Разрешить установку более старой версии (без ключа мастер отказывает на первой странице) |
| `/PURGEDATA` | При удалении стереть `%ProgramData%\ExchangeChecker` (настройки, пароли, журналы); без ключа данные остаются |
| `/LANG=` | Язык интерфейса установщика |

Ключи нечувствительны к регистру, `-` равнозначен `/`.

## Коды выхода

| Код | Смысл |
|-----|-------|
| 0 | Успех |
| 1 | Ошибка (подробности в журнале; при неудачном обновлении выполнен откат на прежнюю версию) |
| 2 | Отменено пользователем |
| 3 | Отказ в понижении версии (нет `/ALLOWDOWNGRADE`) |
| 3010 | Успех, нужна перезагрузка (занятый файл заменится/удалится при перезагрузке) |

## Деинсталлятор

`ExchangeCheckerUninstall.exe` — та же программа без вложенных exe, лежит в папке установки и прописан в Uninstall-ключе. Удаляет: службу, значение HKLM Run, ярлык, источник Event Log, Uninstall-ключ и файлы установки; трей во всех сеансах закрывается. Данные `%ProgramData%\ExchangeChecker` остаются (в мастере — чекбокс «Удалить настройки и пароли», по умолчанию выключен; в тихом режиме — `/PURGEDATA`). Если сам деинсталлятор занят, он удаляется при перезагрузке (код 3010).

| 101 | Информация | Уровень тревоги снизился |
| 102 | Предупреждение | Уровень поднялся до предупреждения |
| 103 | Ошибка | Уровень поднялся до ошибки |

## Целевая платформа сборки

- ОС: **Windows amd64**, совместимость **NT 6.1+** (Windows 7 / Server 2008 R2 и новее)
- Компилятор: **Go 1.20.14**
- Флаги: `GOOS=windows` `GOARCH=amd64` `CGO_ENABLED=0`

## Рекомендации по внедрению: учётная запись SQL для мониторинга

Exchange Checker только читает базы 1С. Для мониторинга заведите **отдельный** логин (SQL-логин или учётную запись Windows/службы) и дайте ему в каждой контролируемой базе **только роль `db_datareader`**:

- не давать `db_owner`, `db_datawriter`, `db_ddladmin`, `sysadmin` и другие серверные роли;
- `VIEW SERVER STATE` и прочие серверные права не нужны (программа не использует `sys.dm_*`);
- не использовать логин `sa` и учётные записи 1С.

Пример (SQL Server 2008, выполняет администратор СУБД; имена — свои):

```sql
CREATE LOGIN [ec_monitor] WITH PASSWORD = N'<сложный пароль>', CHECK_POLICY = ON;
USE [base_1c];
CREATE USER [ec_monitor] FOR LOGIN [ec_monitor];
EXEC sp_addrolemember N'db_datareader', N'ec_monitor';
```

Это основная граница безопасности: даже если в профиль попадёт недопустимый ручной SQL, сервер не позволит изменить данные.

## Рекомендации по внедрению: шифрование подключения

По решению заказчика (сервер — SQL Server 2008 R2 RTM без SP) **основной режим — без шифрования**: новые профили и пресет «SQL Server 2008» создаются с `encrypt = disable`, профили из старого profiles.json без поля `encrypt` читаются так же (PLAN.md §12 п. 31).

- В этом режиме при SQL-аутентификации **пароль передаётся по сети практически открытым текстом** (маскировка TDS обратима), программа показывает предупреждение «пароль SQL передаётся без шифрования» (`sql.warn_plaintext_login`).
- Рекомендуется **Windows-аутентификация** (учётная запись службы или `DOMAIN\user`) — пароль по сети не передаётся, предупреждения нет. Если нужна SQL-аутентификация — только отдельный логин с `db_datareader` (см. выше), не `sa`.
- Если сеть не доверенная, включите в профиле шифрование: «только логин» (`optional`) или «полное» (`on`, при самоподписанном сертификате — «Доверять сертификату сервера»); пресет уже разрешает TLS 1.0 для серверов без обновлений TLS 1.2.
- Если на сервере включено «Force Encryption», режим «без шифрования» не подключится — выберите `optional` или `on`.

## Требования к инсталлятору (фаза 7) из фазы 6

- Источник Event Log `ExchangeChecker`: зарегистрировать `EventMessageFile` с событиями 100–104, **105** («Конфигурация изменена», фаза 6) и 110.
- `secrets.dpapi` служба создаёт сама с DACL SYSTEM + Administrators без наследования (файл, оставшийся от старой версии, служба приводит к этому DACL при старте); инсталлятор не должен давать на него Users-read (каталог `%ProgramData%\ExchangeChecker\` вместе с логами — **только SYSTEM + Administrators**, `D:PAI(A;OICI;FA;;;SY)(A;OICI;FA;;;BA)`, без Users: решение координатора 12.10, PLAN.md §12 п. 90; трей файлы не читает — всё через службу по IPC; каталог с чужим владельцем инсталлятор передаёт Administrators рекурсивно, защищённый DACL `secrets.dpapi` сохраняется).
- Автозапуск трея (PLAN.md §12 п. 72, решение Вики от 03.10, `CHK-CFG-04`): при установке записать в `HKLM\Software\Microsoft\Windows\CurrentVersion\Run` (64-битное представление) стартовое значение `ExchangeCheckerTray` = `"<папка установки>\ExchangeCheckerTray.exe"` (REG_SZ, в кавычках); при деинсталляции — удалить его. Дальше значение ведёт служба по настройке `trayAutostart` (при старте и после сохранения общих настроек).
- Не-администраторам (Interactive Users / Authenticated Users) — право `SERVICE_QUERY_STATUS` в DACL службы (трей сверяет PID сервера канала с PID службы, G7).

## Когда собирать

CI собирает exe и zip и проверяет их **внутри job**, ничего не загружая (CHK-CI-01): версия — тег `vX.Y.Z` → `X.Y.Z`, иначе `0.0.0-ci.<номер запуска>`; zip собирается дважды и сравнивается побайтно. Заказчику zip передаётся из среды нейросети по явной просьбе; канал поставки пересматривается на фазе 8.

Сборка zip — **только по явной просьбе** заказчика (см. POLICY.md / PLAN.md §11 фаза 8).
