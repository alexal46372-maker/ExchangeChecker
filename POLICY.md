# POLICY.md — правила разработки Exchange Checker

Этот документ обязателен для координатора, всех специализированных ботов и любых изменений в репозитории `alexal46372-maker/ExchangeChecker`.

## 1. Заказчик и поставка

- Заказчик **не разработчик**. Пользователь **не пишет код** и **не запускает** Go-компиляцию и сборку.
- Всё это делает нейросеть (координатор и специализированные боты).
- В поставку уходит **только zip с готовыми `.exe`**.
- В zip **запрещены**: `package.json`, `node_modules`, исходники «соберите сами», инструкции по самостоятельной сборке у заказчика.
- Состав zip фиксирует [`DELIVERY.md`](DELIVERY.md).

## 2. Состав продукта

Проект состоит из **трёх** элементов:

1. **Win32-служба** — отдельный `.exe`; на странице «Опции» мастера установки один чекбокс «Запустить службу и запускать автоматически» (по умолчанию включён): включён — служба запускается сразу и автоматически при загрузке (отложенный старт), выключен — тип запуска «Вручную», служба не запускается (PLAN.md §12 п. 90; `CHK-SETUP-10`). Чекбокс остаётся на «Опциях», а не на «Готово» — решение Алекса 20.11.2026 (PLAN.md §12 п. 223).
2. **GUI-трей** — отдельный `.exe`, значок в системном трее (настройки, статусы, алерты).
3. **Инсталлятор** — обычный Win32 `.exe` (папка установки, ярлыки, запись в «Установка и удаление программ», деинсталлятор).

Кратко: заказчик получает готовый exe (инсталлятор); код только WinAPI и Go 1.20.14 под Win7+; автотест на каждую фичу; без «дособерите у себя».

## 3. Toolchain и целевая ОС

- `go.mod` = **`go 1.20`**.
- Полная сборка **только** в среде нейронки.
- Toolchain: **Go 1.20.14**, **Windows amd64**, **без CGO**.
- Цель: **Windows 7 / Server 2008 R2 (NT 6.1+) и новее**.
- Go 1.21+ официально отбросил Win7 — **toolchain не поднимать** без явного решения снять поддержку NT 6.1.

## 4. Только WinAPI

- На Windows **нельзя** вызывать `cmd`, PowerShell, `wmic`, `sc`, `net` и прочие helper-процессы.
- Запуск **собственного exe продукта** через WinAPI — не helper-процесс: трей перезапускает себя с `--settings` (`ShellExecuteExW runas`), инсталлятор после установки/обновления запускает трей без повышения в сеансе пользователя (токен `explorer.exe` + `CreateProcessWithTokenW`, PLAN.md §12 п. 90). `os/exec` в `cmd/`, `internal/` и `tools/` запрещён, включая тесты (CHK-POL-01).
- **Единственное исключение для `os/exec`:** тесты пакета `checks/` (`checks/*_test.go`) могут вызывать тулчейн Go (`go build`), чтобы проверить собранные exe (`TestCHK_RES_01_LinkedExe`, `checks/res01_test.go`). В продукт эти тесты не входят; CHK-POL-01 проверяет, что больше нигде `os/exec` нет.
- Только `syscall` и стандартная библиотека Go; `golang.org/x/sys` не используется (граф трея — CHK-TRAY-10, граф установщика — CHK-SETUP-11).
- **Исключение — драйвер MSSQL (решение Алекса 20.11.2026, PLAN.md §12 п. 223):** `github.com/microsoft/go-mssqldb v1.8.2` (версия из `go.mod`) и его транзитивные зависимости из `go.mod` (`// indirect`): `github.com/golang-sql/civil v0.0.0-20220223132316-b832511892a9`, `github.com/golang-sql/sqlexp v0.1.0`, `github.com/google/uuid v1.6.0`, `golang.org/x/crypto v0.24.0`, `golang.org/x/text v0.16.0`. Драйвер импортирует только `internal/sqlcheck`, поэтому он попадает только в службу (`ExchangeCheckerSvc.exe`). В графах трея и установщика его нет (CHK-TRAY-10, CHK-SETUP-11). `golang.org/x/sys` драйвер в граф службы не приносит (`go list -deps ./cmd/exchsvc`, windows/amd64). Других сторонних библиотек не добавлять.
- Сеть — через `internal/hcwinnet` (или согласованный внутренний сетевой пакет проекта; helper-процессы запрещены).
- Только штатный UI: допустимы Win32 installer и Win32 GUI-трей.
- Брандмауэр Windows — только через COM `INetFwPolicy2`/`INetFwRule` (фаза 11, CHK-SETUP-13); `netsh` и helper-процессы запрещены (как и для SCM/реестра).

## 5. Автотесты и merge

- Автотест покрывает **весь** продукт.
- Любая фича сразу получает свой **check ID**; **без check ID мержить нельзя**.
- Проверяются: API, Win32-служба, Win32 GUI-трей, installer, `internal/*`, WinAPI-only, Go 1.20.14 и поддержка NT 6.1+.

## 6. Репозиторий и процесс

- Единственный рабочий репозиторий: `https://github.com/alexal46372-maker/ExchangeChecker.git`.
- Не создавать альтернативные копии проекта вне этого репозитория.
- Сначала анализировать существующую архитектуру; не переписывать рабочие компоненты без необходимости.
- Перед крупными изменениями — план на согласование.
- После изменений — проверки и доступные тесты; ошибки исправлять самостоятельно.
- Коммит — только после успешной проверки; в конце работы коммит обязателен.
- Сборка `.exe` и упаковка в `.zip` **для поставки** (релиз, zip заказчику) — **только по слову заказчика**. CI (`ci.yml`) в каждом прогоне собирает exe и zip только для проверки (шаг «release build + delivery zip»: CHK-RES-01, CHK-VER-01, CHK-DELIV-01, CHK-SETUP-19) и ничего из этого не загружает. Уточнение по решению Алекса 20.11.2026 (PLAN.md §12 п. 223), смысл правила не изменился.
- CI (CHK-CI-01) ничего не загружает. **Исключения (ровно два):** (1) `.github/workflows/release.yml` (запуск только вручную — `workflow_dispatch` — или пушем тега `v*`; `permissions: contents: read`) загружает **ровно один** артефакт — zip поставки — со сроком хранения **7 дней**; (2) **фаза 11, `CHK-TRAY-46`, одобрено Кончитой:** `.github/workflows/ci.yml` загружает **ровно один** артефакт `ui-screens` — PNG-скриншоты окон трея (только RU с фазы 13, CHK-TRAY-86; все сцены — 96 и 144 dpi; с фазы 17, CHK-TRAY-110, ещё три снимка окна настроек в экспертном режиме на вкладке «Базы данных»: 96 dpi, 120 dpi и 96 dpi на рабочей области 1024×768 — снимки 120 dpi оставлены решением Алекса 20.11.2026, PLAN.md §12 п. 223; окна показываются за пределами экрана) — **только из windows-job**, срок хранения **7 дней**; ни exe, ни zip в нём нет. Других артефактов нет; это проверяет `TestCHK_CI_01_ArtifactsOnlyRelease`.
- CI (linux-job) проверяет форматирование: шаг `gofmt (CHK-CI-02)` запускает `gofmt -l .` из Go 1.20.14, при непустом списке печатает файлы и `gofmt -d .` и падает; неотформатированный код в `main` не вливается (решение Алекса 20.11.2026, PLAN.md §12 п. 224).
- В отчётах всегда: **выполнено / частично / не выполнено**.

## 7. Роли ботов

- Координатор / архитектор планирует и распределяет задачи.
- Реальные правки кода и параллельную работу выполняют **специализированные боты**.
- Правила доступа к репозиторию и этот `POLICY.md` действуют для всех одинаково.

## 8. Продуктовые границы (кратко)

- Служба в цикле читает из указанных MSSQL-баз времена обмена 1С 8.1 по точкам обмена (отправка / приём).
- Трей: ПКМ — «Настройки» / «О программе»; ЛКМ — статусы настроенных профилей; алерты warning/error — модальные поверх всех окон + звук по порогам из настроек. Окно тревоги не закрывается — только «Подтвердить», «Звук выкл»/«Звук вкл» и сворачивание (фаза 16, PLAN.md §12 п. 221); пока окно тревоги свёрнуто, экран не мигает, при разворачивании мигание возобновляется (решение Алекса 17.11.2026, фаза 17, PLAN.md §12 п. 220, 222); после «Подтвердить» экран снова мигает на следующей неудачной проверке (решение Алекса 17.11.2026, там же, п. 220). Встроенный сигнал «Тон» сначала звучит через системный динамик (PC speaker) службы Exchange Checker; при недоступности или отказе — через колонки (звуковой выход). Решение 03.11.2026 (`CHK-TRAY-97`, «только через колонки») отменено решением Алекса 10.11.2026 (фаза 14, см. исключение ниже). **С фазы 16** (задание Алекса 16.11.2026, PLAN.md §12 п. 221, `CHK-TRAY-98`/`99`/`105`) у каждого уровня есть выбор «Вывод звука» для «Тона»: «Системный динамик» (по умолчанию; поведение выше), «Колонки» или «Динамик и колонки»; звуковой файл звучит только через колонки; громкость — только общий ползунок в меню значка. Подпись в UI — «Тон». Служба принимает `speaker_tone` только если есть активная тревога warning/error, либо в режиме прослушивания: не чаще одного раза в 10 с на всю службу и длительность до 5 с; иначе `notify.speaker_denied`. Остановка своего тона (`durMs: 0`) разрешена всегда (`CHK-IPC-20`).
- **Исключение «без драйверов» (решение Алекса 10.11.2026, фаза 14):** для встроенного сигнала «Тон» через системный динамик (PC speaker) на Win7 x64 установщик ставит **один** сторонний драйвер ядра — оригинальный подписанный `inpoutx64.sys` от highrez (`third_party/inpout/`, MIT), без изменений, sha256 зашит в `config.InpOutSHA256`. Служба `ExchangeCheckerInpOut` (`SERVICE_KERNEL_DRIVER`, `SERVICE_DEMAND_START`, запуск только SY/BA); установщик её не запускает, EC Service сверяет sha256 и запускает по требованию. Драйвер числится уязвимым (loldrivers.io; блок-лист Microsoft блокирует другие сборки InpOutx64): пока он загружен, любой локальный процесс может открыть `\\.\inpoutx64` и получить доступ к портам и физической памяти. Риск принят заказчиком. Других драйверов не добавлять; замена файла — только на оригинал из официального дистрибутива с повторными стоп-проверками лицензии и подписи (`CHK-SETUP-19`/`20`).
- Связь служба ↔ трей — **постоянное** соединение на одной машине.
- Настройки (серверы, базы, интервалы опроса и пороги) хранятся в файлах; логин SQL — в `profiles.json`, пароль — только зашифрованным в `secrets.dpapi`, см. §9; в GUI обязателен «Тест» соединения к SQL.

## 9. Учётные данные подключений к БД (обязательно)

> **Решение Алекса 20.11.2026, отменяет редакцию от 13.10.2026** (PLAN.md §12 п. 223): «Пароль: поправь правило под код, пусть хранится зашифрованным». Прежняя редакция требовала «нигде не сохранять на диске» и держать учётные данные «только в оперативной памяти» службы; она отменена. Ниже — фактическое поведение кода v0.17.0.

- **Логин** SQL-аутентификации хранится открытым текстом в `%ProgramData%\ExchangeChecker\profiles.json` — поле `login` профиля (`internal/model/profile.go`; CHK-CFG-01).
- **Пароль** хранится только зашифрованным, в `%ProgramData%\ExchangeChecker\secrets.dpapi`, по ID профиля (`internal/config/secrets.go`).
  - Шифрование: `CryptProtectData` с `CRYPTPROTECT_LOCAL_MACHINE | CRYPTPROTECT_UI_FORBIDDEN` и дополнительной энтропией `ExchangeChecker/secrets.dpapi/v1` (CHK-CFG-01, CHK-CFG-02).
  - Ключ DPAPI машинный, поэтому граница доступа — права на файлы. DACL файла `secrets.dpapi`: `D:P(A;;FA;;;SY)(A;;FA;;;BA)`, только LocalSystem и администраторы; DACL приводится к этому виду при записи и при старте службы (CHK-CFG-03). Папка `%ProgramData%\ExchangeChecker`: SY+BA, без Users (CHK-SETUP-05).
  - В `profiles.json` и `settings.json` пароля нет. Есть только признак `hasPassword`, его выставляет служба по `secrets.dpapi` (CHK-CFG-03).
- **Пишет и читает `secrets.dpapi` только служба (LocalSystem).**
  - Трей передаёт пароль службе командой `save_profile` по IPC, только из окна повышенного администратора (CHK-IPC-06, CHK-CFG-03). Сам трей файлы конфигурации не пишет (CHK-TRAY-06).
  - Служба расшифровывает пароль для опроса и для `test_profile` / `sql_test_steps` по сохранённому профилю (CHK-IPC-03, CHK-IPC-13).
- **Служба никогда не возвращает пароль:**
  - `get_config` и другие ответы содержат только `hasPassword` (CHK-CFG-03, CHK-IPC-06);
  - `export_config` выгружает конфигурацию без паролей (CHK-CFG-06);
  - копия профиля создаётся без пароля и с признаком `needPassword` (CHK-CFG-08).
- **Где пароля и логина нет:**
  - Пароль не попадает в лог службы, в ответы IPC и в файлы папки конфигурации (кроме `secrets.dpapi`), даже если он есть в тексте ошибки драйвера (CHK-IPC-03, `TestCHK_IPC_03_CategoriesNoPassword`).
  - При форматировании `IPCRequest` пароль маскируется (CHK-IPC-03).
  - В строку подключения (DSN) пароль не входит (CHK-SQL-01).
  - В логе трея нет паролей и логинов — они маскируются (CHK-TRAY-28).
  - В истории опросов нет ни логина, ни пароля (CHK-SVC-03).
  - Журнал событий и реестр: по коду пароль и логин туда не пишутся, но **отдельного check ID на это пока нет** (PLAN.md §12 п. 223).
- **Удаление пароля:**
  - `clearPassword` в `save_profile` и переход профиля на Windows-аутентификацию (CHK-CFG-03);
  - удаление профиля (CHK-IPC-06, `TestCHK_IPC_06_DeleteSettingsGetConfig`);
  - удаление программы с ключом `/PURGEDATA` стирает всю папку `%ProgramData%\ExchangeChecker` (CHK-SETUP-12).
- Сохранённый пароль переживает перезапуск службы: служба читает его из `secrets.dpapi` при загрузке конфигурации (CHK-CFG-01, CHK-MON-04).
- Правило архитектурное и обязательно для всех ботов и разработчиков; на каждое требование — автотест и check ID.
