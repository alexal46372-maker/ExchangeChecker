# POLICY.md — правила разработки Exchange Checker

Этот документ обязателен для координатора, всех специализированных ботов и любых изменений в репозитории `alexal46372-maker/ExchangeChecker`.

## 1. Заказчик и поставка

- Заказчик **не разработчик**. Пользователь **не пишет код** и **не запускает** Go-компиляцию и сборку.
- Всё это делает нейросеть (координатор и специализированные боты).
- В поставку уходит **только zip с готовыми `.exe`**.
- В zip **запрещены**: `package.json`, `node_modules`, исходники «соберите сами», инструкции по самостоятельной сборке у заказчика.
- Состав zip фиксирует [`DELIVERY.md`](DELIVERY.md).

## 2. Состав продукта

Проект состоит из **трёх** элементов:

1. **Win32-служба** — отдельный `.exe`; на экране «Готово» один чекбокс «Запустить службу и запускать автоматически» (по умолчанию включён): включён — служба запускается сразу и автоматически при загрузке (отложенный старт), выключен — тип запуска «Вручную», служба не запускается (PLAN.md §12 п. 90).
2. **GUI-трей** — отдельный `.exe`, значок в системном трее (настройки, статусы, алерты).
3. **Инсталлятор** — обычный Win32 `.exe` (папка установки, ярлыки, запись в «Установка и удаление программ», деинсталлятор).

Кратко: заказчик получает готовый exe (инсталлятор); код только WinAPI и Go 1.20.14 под Win7+; автотест на каждую фичу; без «дособерите у себя».

## 3. Toolchain и целевая ОС

- `go.mod` = **`go 1.20`**.
- Полная сборка **только** в среде нейронки.
- Toolchain: **Go 1.20.14**, **Windows amd64**, **без CGO**.
- Цель: **Windows 7 / Server 2008 R2 (NT 6.1+) и новее**.
- Go 1.21+ официально отбросил Win7 — **toolchain не поднимать** без явного решения снять поддержку NT 6.1.

## 4. Только WinAPI

- На Windows **нельзя** вызывать `cmd`, PowerShell, `wmic`, `sc`, `net` и прочие helper-процессы.
- Запуск **собственного exe продукта** через WinAPI — не helper-процесс: трей перезапускает себя с `--settings` (`ShellExecuteExW runas`), инсталлятор после установки/обновления запускает трей без повышения в сеансе пользователя (токен `explorer.exe` + `CreateProcessWithTokenW`, PLAN.md §12 п. 90). `os/exec` в `cmd/`, `internal/` и `tools/` запрещён, включая тесты (CHK-POL-01).
- **Единственное исключение для `os/exec`:** тесты пакета `checks/` (`checks/*_test.go`) могут вызывать тулчейн Go (`go build`), чтобы проверить собранные exe (`TestCHK_RES_01_LinkedExe`, `checks/res01_test.go`). В продукт эти тесты не входят; CHK-POL-01 проверяет, что больше нигде `os/exec` нет.
- Только `syscall` и стандартная библиотека Go (`golang.org/x/sys` не используется, CHK-TRAY-10).
- Сеть — через `internal/hcwinnet` (или согласованный внутренний сетевой пакет проекта; helper-процессы запрещены).
- Только штатный UI: допустимы Win32 installer и Win32 GUI-трей.
- Брандмауэр Windows — только через COM `INetFwPolicy2`/`INetFwRule` (фаза 11, CHK-SETUP-13); `netsh` и helper-процессы запрещены (как и для SCM/реестра).

## 5. Автотесты и merge

- Автотест покрывает **весь** продукт.
- Любая фича сразу получает свой **check ID**; **без check ID мержить нельзя**.
- Проверяются: API, Win32-служба, Win32 GUI-трей, installer, `internal/*`, WinAPI-only, Go 1.20.14 и поддержка NT 6.1+.

## 6. Репозиторий и процесс

- Единственный рабочий репозиторий: `https://github.com/alexal46372-maker/ExchangeChecker.git`.
- Не создавать альтернативные копии проекта вне этого репозитория.
- Сначала анализировать существующую архитектуру; не переписывать рабочие компоненты без необходимости.
- Перед крупными изменениями — план на согласование.
- После изменений — проверки и доступные тесты; ошибки исправлять самостоятельно.
- Коммит — только после успешной проверки; в конце работы коммит обязателен.
- Сборка `.exe` и упаковка в `.zip` — **только по явной просьбе** заказчика.
- CI (CHK-CI-01) ничего не загружает. **Исключения (ровно два):** (1) `.github/workflows/release.yml` (запуск только вручную — `workflow_dispatch` — или пушем тега `v*`; `permissions: contents: read`) загружает **ровно один** артефакт — zip поставки — со сроком хранения **7 дней**; (2) **фаза 11, `CHK-TRAY-46`, одобрено Кончитой:** `.github/workflows/ci.yml` загружает **ровно один** артефакт `ui-screens` — PNG-скриншоты окон трея (RU/EN, 96 и 144 dpi; окна показываются за пределами экрана) — **только из windows-job**, срок хранения **7 дней**; ни exe, ни zip в нём нет. Других артефактов нет; это проверяет `TestCHK_CI_01_ArtifactsOnlyRelease`.
- В отчётах всегда: **выполнено / частично / не выполнено**.

## 7. Роли ботов

- Координатор / архитектор планирует и распределяет задачи.
- Реальные правки кода и параллельную работу выполняют **специализированные боты**.
- Правила доступа к репозиторию и этот `POLICY.md` действуют для всех одинаково.

## 8. Продуктовые границы (кратко)

- Служба в цикле читает из указанных MSSQL-баз времена обмена 1С 8.1 по точкам обмена (отправка / приём).
- Трей: ПКМ — «Настройки» / «О программе»; ЛКМ — статусы настроенных профилей; алерты warning/error — модальные поверх всех окон + звук через PC speaker по порогам из настроек.
- Связь служба ↔ трей — **постоянное** соединение на одной машине.
- Настройки (серверы, базы, интервалы опроса и пороги) хранятся в файлах; учётные данные SQL — **только в памяти**, см. §9; в GUI обязателен «Тест» соединения к SQL.

## 9. Учётные данные подключений к БД (обязательно)

- Имя пользователя и пароль для подключения к базам **нигде не сохраняются на диске**: ни в конфигах (`profiles.json`, `settings.json`), ни в логах, ни в журнале событий, ни в secrets-файлах (в т.ч. `secrets.dpapi`), ни в реестре.
- Учётные данные вводятся пользователем после запуска службы и хранятся **только в оперативной памяти** процесса службы, пока она работает.
- При остановке службы учётные данные **обязательно удаляются из памяти** (буферы затираются, ссылки обнуляются).
- После каждого старта службы учётные данные задаются заново; до этого опрос профилей с SQL-аутентификацией не выполняется.
- Правило архитектурное и обязательно для всех ботов и разработчиков; на каждое требование — автотест и check ID.
