# Ручная приёмка Exchange Checker на Windows 7 / Server 2008 R2 (черновик)

*Сверено с кодом v0.17.0 (20.11.2026).*

Документ для человека, который проверяет программу руками на реальной машине. Пишем простыми словами. Всё, что взято из кода или DELIVERY.md, считается фактом; пункты с пометкой **[не проверено]** — предположения, их нужно подтвердить на первой же приёмке.

Что нужно заранее:

- Windows 7 SP1 или Windows Server 2008 R2 (64-бит), учётная запись администратора.
- Zip поставки `ExchangeChecker-<версия>.zip` (внутри один файл `Exchange Checker <версия>.exe` — с пробелами, фаза 13). Его собирает workflow `release`, координатор выкладывает его на странице релиза GitHub (текущий — [v0.17.0](https://github.com/alexal46372-maker/ExchangeChecker/releases/tag/v0.17.0)). Артефакт GitHub скачивается как **zip в zip**: внешний архив (обёртка GitHub) содержит внутренний zip поставки с тем же именем. Координатор распаковывает внешний архив, сверяет sha256 внутреннего zip с журналом сборки и передаёт для приёмки только внутренний zip. Если вам достался внешний архив — распакуйте его один раз и работайте с внутренним zip. Для сборок по кнопке версия вида `0.0.0-rel.N`, для релиза — `X.Y.Z` (например `0.17.0`).
- Доступ к SQL Server с базой 1С и отдельным логином с ролью `db_datareader` (см. DELIVERY.md).
- Записывайте для каждого шага: «ОК» или что пошло не так + снимок экрана.

Пути, которые понадобятся:

## 1. Интерактивная установка

1. Распакуйте zip, запустите `Exchange Checker <версия>.exe`. Должен появиться запрос UAC (программа требует прав администратора). На неподписанный файл Windows может показать предупреждение — см. раздел 11.
2. Мастер и вся программа — только на русском (фаза 13, CHK-TRAY-86); ключ `/LANG=` из старых сценариев принимается и игнорируется. Проверьте: все надписи на русском, текст не обрезан.
3. Страницы мастера: «Приветствие» → «Папка» → «Опции» → «Установка» → «Готово». Кнопка «Назад» работает до начала копирования, «Отмена» спрашивает подтверждение.
4. На странице «Опции»: чекбоксы «Ярлык в меню «Пуск»», «Создать ярлык на рабочем столе» и «Запустить службу и запускать автоматически» (все включены по умолчанию).
5. Отмена на любой странице до установки → программа ничего не меняет (код выхода 2).

## 2. Кнопка «Обзор…»

1. На странице «Папка» нажмите «Обзор…», выберите обычную папку на диске C: → путь подставляется в поле.
2. Нажмите «Обзор…» и выберите не папку файловой системы (например «Библиотеки» или «Сеть») → должна появиться ошибка «Не удалось получить путь выбранной папки», а не тихая отмена. **[не проверено на Win7 вручную]**
3. «Отмена» в окне выбора → поле не меняется.
4. Сетевой диск или несуществующий диск в поле → мастер не пускает дальше (папка установки должна быть на локальном фиксированном диске).
5. При обновлении поле папки только для чтения.

## 3. Запуск трея на странице «Готово»

1. На «Готово» отмечен чекбокс «Запустить Exchange Checker (значок в области уведомлений)». Нажмите «Готово» → через несколько секунд в области уведомлений появляется значок.
2. Откройте «Диспетчер задач» → процесс `ExchangeCheckerTray.exe` запущен **от имени вашего пользователя**, не от администратора и не от SYSTEM (трей запускается с правами `explorer.exe`). **[не проверено вручную; в CI не покрыто]**
3. Снимите чекбокс → трей не запускается.
4. При ошибке установки на «Готово» показан текст ошибки и путь к журналу.

## 4. Ярлык в меню «Пуск»

1. «Пуск» → «Все программы» → `Exchange Checker` → `Exchange Checker` запускает трей. Ярлык общий для всех пользователей.
2. Если на «Опциях» сняли галочку ярлыка (или ключ `/NOSHORTCUT`) — ярлыка нет.
3. Ярлык на общем рабочем столе: есть, если отмечено «Создать ярлык на рабочем столе»; нет — при снятой галке или ключе `/NODESKTOPSHORTCUT` (выбор запоминается для обновлений).
4. После удаления программы оба ярлыка и папка `Exchange Checker` в меню исчезают.

## 4a. Правило брандмауэра для SQL Browser (фаза 11) **[проверить вручную на Win7]**

1. После установки (в т.ч. тихой `/S`): «Панель управления» → «Брандмауэр Windows» → «Дополнительные параметры» → «Правила для входящих подключений» → ровно одно правило с именем **`Exchange Checker (SQL Browser)`**.
2. Свойства правила: программа = полный путь к `ExchangeCheckerSvc.exe` в папке установки; протокол UDP; локальные порты — любые (в оснастке часто «Все локальные порты»); удалённые порты — **1434**; удалённые адреса — **локальная подсеть** (`LocalSubnet`); направление — входящее; действие — разрешить; включено; группа — `Exchange Checker`; профили — **домен и частная** (общественная / Public **не** включена).
3. Повторная установка / обновление поверх: правило по-прежнему **одно** (без дубликатов).
4. После удаления программы правила с этим именем нет.
5. Если служба брандмауэра выключена: установка всё равно завершается успешно; в `%TEMP%\ExchangeCheckerSetup-*.log` есть строка `WARNING` про firewall — это ожидаемо.
6. Если сеть помечена как «Общественная» (Public), обнаружение через SQL Browser не работает: правило покрывает только Domain|Private (домен и частная). Переключите сеть на «Домашняя» или «Рабочая».
7. Если при установке активен профиль «Общественная» (Public): установка завершается успешно, в `%TEMP%\ExchangeCheckerSetup-*.log` есть строка `WARNING` про профиль Public — это ожидаемо.
8. Ограничение `LocalSubnet`: если SQL Server стоит на компьютере с несколькими сетевыми адресами и отвечает с адреса из другой подсети, ответ SQL Browser не пройдёт — такой сервер нужно указать вручную.

## 5. Служба и Event Log

1. `services.msc` → служба `ExchangeChecker`: состояние «Работает», тип запуска «Автоматически (отложенный запуск)», при сбое — перезапуск.
2. Event Log → «Приложение», источник `ExchangeChecker`: при старте службы событие 100. Текст события читается нормально (без фразы «Не найдено описание для события…»).
3. Таблица событий:

| ID | Тип | Когда |
|----|-----|-------|
| 100 | Информация | служба запущена / остановлена |
| 101 | Информация | уровень тревоги снизился |
| 102 | Предупреждение | нет обмена дольше порога предупреждения |
| 103 | Ошибка | нет обмена дольше порога ошибки или база недоступна |
| 104 | Информация | тревога подтверждена из трея |
| 105 | Информация | конфигурация изменена |
| 110 | Ошибка | ошибка конфигурации / внутренняя ошибка |

4. Остановите службу → трей показывает «Служба Exchange Checker не запущена» (серый значок **[цвет не проверен]**). Запустите снова → «Служба работает».

## 6. Настройка подключения к SQL

1. Правый клик по значку трея → «Настройки…». Порядок меню: «Настройки…» → «Состояние…», «Проверить сейчас», «Уведомления о просрочке», «Служба» ▸, ползунок «Громкость», «Как закрепить значок…», «Сводка…» (если служба поддерживает) → «О программе» → «Выход» (**без** «Звук тревог…», «Язык» и «Тема» — фаза 13). В окне настроек вкладки «Общие настройки» и «Базы данных» (в обоих режимах), в «Экспертном режиме» ещё «Уведомления Viber», «Уведомления e-mail», «Telegram». Звук тревог — раздел «Звук» на «Общие настройки». Обычный пользователь видит окно «только чтение»; для изменений — кнопка «Изменить (администратор)» (запрос UAC).
2. «Добавить» → заполните: «Название», «Сервер (хост)», «Экземпляр» или «Порт», «База данных», «Аутентификация» (SQL Server — логин и пароль, или Windows — учётная запись службы), «Шифрование».
3. Для SQL Server 2008 R2 без обновлений: основной режим — «Без шифрования» (появится предупреждение, что пароль передаётся почти открытым текстом); при необходимости TLS — «Разрешить TLS 1.0 (SQL Server 2008)».
4. «Проверить подключение» → «успешно» с версией сервера, либо понятная ошибка.
5. «Таблицы обмена…» → «Найти таблицы» → выбрать вариант → «Проверить» → «Применить» → «Сохранить». Строка «Таблицы обмена: настроены».
6. Пароль хранится зашифрованным (`secrets.dpapi`); в `profiles.json` пароля быть не должно.

## 7. Цвета баз в трее

Левый клик по значку — список баз, у каждой цветной квадрат и текст:

| Цвет | Текст | Значение |
|------|-------|----------|
| зелёный | норма | обмен в пределах порогов |
| жёлтый | предупреждение | нет обмена дольше порога предупреждения (по умолчанию 30 мин) |
| красный | ошибка | нет обмена дольше порога ошибки (по умолчанию 60 мин) или база недоступна |
| серый | выключена / ожидание опроса / «последние известные данные» | база отключена, ещё не опрошена или нет свежих данных от службы |

Проверьте: подменю базы показывает точки обмена со временем отправки/приёма (UTC+3); клик по базе снимает или ставит галочку — опрос базы выключается или включается. При тревоге появляется окно тревоги и звук (если включён «Звуковой сигнал тревоги» в «Общих настройках»). Пороги и интервал опроса (по умолчанию 60 с) меняются в «Общих настройках».

**Окно тревоги и мигание (фазы 13, 16, 17):**

1. В окне тревоги кнопки «Подтвердить», «Звук выкл» / «Звук вкл»; кнопки «Закрыть» нет, крестик неактивен, Alt+F4 и Esc ничего не делают. Полоса заголовка мигает красным и чёрным.
2. Значок в трее и облачко у часов мигают: красный (ошибка) или жёлтый (предупреждение) ↔ чёрные стрелки с хромовой обводкой.
3. При ошибке обмена (если включено «Мигание экрана при ошибке обмена») мигает весь экран. Сверните окно тревоги — мигание экрана сразу прекращается, звук и значок продолжают. Разверните окно кнопкой на панели задач — мигание возобновляется.
4. «Подтвердить» — мигание гаснет; на следующей неудачной проверке экран снова мигает, пока обмен не восстановится (решение Алекса 17.11.2026).
5. Новая тревога при свёрнутом окне разворачивает его, и мигание возобновляется.

**Звук «Тон» (фазы 14 и 16).** У уровней «Предупреждение» и «Ошибка» выбор «Тон» или файл; для «Тона» — «Вывод звука»: «Системный динамик» (по умолчанию: PC speaker через службу Exchange Checker; при недоступности или отказе службы — через колонки / звуковую карту), «Колонки» или «Динамик и колонки». Файл звучит только через колонки. Громкости у уровня нет — только общий ползунок «Громкость» в меню значка (0 % — без звука). Решение 03.11.2026 (`CHK-TRAY-97`, «только через колонки») отменено решением Алекса 10.11.2026. Запасной путь трея: синус через `PlaySound` (`SND_MEMORY`) с общей громкостью → если звукового устройства нет — `Beep` → если и он не сработал — системный звук `MessageBeep(MB_ICONHAND)` («Критическая ошибка»). Каждый переход на запасной вариант один раз записывается в журнал трея. Ручная проверка системного динамика — в §13.

## 8. Обновление поверх старой версии

1. Установите старую версию, настройте базу, убедитесь, что служба работает и трей запущен.
2. Запустите новый `Exchange Checker <версия>.exe`. Мастер пишет «Установлена версия X, будет обновлена до Y»; папка не меняется, чекбокс службы недоступен и показывает прежнее состояние.
3. После обновления: трей старой версии закрыт, служба работает, тип запуска тот же, настройки и пароли на месте, в «Программах и компонентах» новая версия.
4. Запуск более старой версии поверх новой без `/ALLOWDOWNGRADE` → отказ сразу на первой странице, «Далее» недоступна; «Отмена» → код 3.
5. Если обновление не удалось, программа откатывается на прежнюю версию (код 1, причина в журнале установки).

## 9. Тихая установка `/S`

Команды (cmd.exe «от имени администратора»; `start /wait` нужен, чтобы дождаться кода выхода):

```
start /wait "" "Exchange Checker <версия>.exe" /S /LOG=C:\ec-setup.log
echo %ERRORLEVEL%
```

Дополнительные ключи: `/DIR=<папка>`, `/NOSTART` (не запускать службу и не ставить автозапуск), `/NOSHORTCUT`, `/NODESKTOPSHORTCUT`, `/ALLOWDOWNGRADE`; `/LANG=` из старых сценариев принимается и игнорируется. В тихом режиме **никаких окон** и трей после установки не запускается.

Коды выхода: `0` — успех, `1` — ошибка, `2` — отменено, `3` — отказ в понижении версии, `3010` — успех, нужна перезагрузка.

## 10. Удаление (с настройками и без)

1. «Панель управления» → «Программы и компоненты» → Exchange Checker → «Удалить». Окно подтверждения с чекбоксом «Удалить настройки и пароли» (по умолчанию **выключен**).
2. Без чекбокса: служба, служба драйвера `ExchangeCheckerInpOut`, ярлыки, автозапуск трея, правило брандмауэра, запись в «Программах и компонентах», источник Event Log и файлы программы удалены; трей закрыт во всех сеансах; `%ProgramData%\ExchangeChecker` **остаётся**. Повторная установка подхватывает прежние настройки.
3. С чекбоксом: `%ProgramData%\ExchangeChecker` тоже удалён.
4. Тихо: `"%ProgramFiles%\Exchange Checker\ExchangeCheckerUninstall.exe" /uninstall /S` (данные остаются) или с `/PURGEDATA` (данные удаляются).
5. Код 3010 — нужна перезагрузка (деинсталлятор удалится после неё); это нормально.

## 12. Что прислать, если что-то не так

1. Описание: что делали, что ожидали, что получили; версия из «О программе» или из свойств `Exchange Checker <версия>.exe` (вкладка «Подробно»).
2. Код выхода (для `/S`: `echo %ERRORLEVEL%` после `start /wait`).
3. Журнал установки: `%TEMP%\ExchangeCheckerSetup-*.log` или файл из `/LOG=`.
4. Журнал службы: `%ProgramData%\ExchangeChecker\logs\exchsvc.log` (папка доступна только администраторам).
5. Event Log: «Просмотр событий» → «Приложение» → «Фильтр текущего журнала» → источник `ExchangeChecker` → «Сохранить отфильтрованные события как…» (`.evtx`).
6. Снимки экрана окна с ошибкой и, при проблемах с треем, меню трея.
7. **Не присылайте** `secrets.dpapi` и пароли; `profiles.json` можно (паролей в нём нет).

## 13. Системный динамик (InpOutx64, фаза 14, CHK-SVC-12)

Целевая машина — Windows 7 SP1 / Server 2008 R2 **64-бит**. На Windows 10 и 11 с включённым HVCI официальный `inpoutx64.sys` входит в blocklist уязвимых драйверов Microsoft (тот же файл есть на [LOLDrivers](https://www.loldrivers.io/drivers/91ff1575-9ff2-46fd-8bfe-0bb3e3457b7f/), sample 3, SHA-256 `f8965fdce668692c3785afa3559159f9a18287bc0d53abb21902895a8ecf221b`). На Windows 7 HVCI нет; риск принят Алексом 10.11.2026.

Служба принимает `speaker_tone` только если есть активная тревога warning/error в снимке (`Alerts`, в том числе уже подтверждённые), либо в режиме прослушивания: не чаще одного раза в **10 с на всю службу** и длительность до **5 с** (большее значение обрезается). Иначе `notify.speaker_denied`. Остановка своего тона (`durMs: 0`) разрешена всегда.

Как получить настоящую тревогу для длинного тона: настройте профиль к реальной базе 1С и дождитесь, пока отставание превысит порог warning/error (или сделайте SQL-сервер недоступным, чтобы профиль ушёл в ошибку). Тревога остаётся в `Alerts` и после «Подтвердить». **Не используйте `alarm_test` для этого:** он только рассылает тестовый push и не создаёт активную тревогу службы, поэтому `speaker_tone` остаётся в режиме прослушивания (до 5 с, раз в 10 с). Смешанный звук (пищалка службы и колонки трея во время `alarm_test`) — ожидаемо.

Автотест, который реально открывает драйвер, **не входит в обычный CI**. Его запускают только на машине, где служба драйвера уже установлена:

```
go test -tags inpout_e2e -count=1 ./internal/pcspeaker -run TestCHK_SVC_12_RealInpOut
```

Если драйвер не загружается, тест должен завершиться ошибкой (не Skip). Ниже — ручные шаги той же проверки.

1. После установки Exchange Checker откройте `services.msc`. Должна быть служба **`ExchangeCheckerInpOut`**: тип «Драйвер ядра» (`SERVICE_KERNEL_DRIVER`), запуск «Вручную» (`DEMAND_START`), состояние **«Остановлена»** (инсталлятор службу не запускает).
2. В свойствах службы посмотрите «Путь к исполняемому файлу» (ImagePath). Посчитайте SHA-256 этого файла (в PowerShell: `Get-FileHash -Algorithm SHA256 <путь>`). Должно получиться ровно `f8965fdce668692c3785afa3559159f9a18287bc0d53abb21902895a8ecf221b` (официальный подписанный `inpoutx64.sys` из InpOut32 1.5.0.1 Highrez: https://www.highrez.co.uk/Downloads/InpOut32/default.htm , пакет `InpOutBinaries`).
3. Запустите службу `ExchangeChecker` (не InpOut). Подключите трей (или IPC-клиент) и отправьте `{cmd:"speaker_status"}`. Ожидается `available=true`, `driverVersion="1.2 x64"`. Пока тон не звучит, `ExchangeCheckerInpOut` по-прежнему **остановлена**.
4. Прослушивание (без тревоги): отправьте `{cmd:"speaker_tone", freqHz:440, durMs:500}`. Должен прозвучать тон 440 Гц через системную пищалку (500 мс ≤ 5 с). Пока тон идёт, служба `ExchangeCheckerInpOut` — «Работает».
5. После окончания тона подождите около **2 секунд**. `ExchangeCheckerInpOut` должна снова стать «Остановлена».
6. Сразу (ещё внутри окна 10 с), даже с другого подключения, отправьте ещё один `speaker_tone` (хотя бы на 500 мс). Ожидается `notify.speaker_denied`. Не отправляйте здесь 10-секундный тон — без тревоги он был бы обрезан до 5 с или отклонён.
7. Подождите **10 с** после шага 4 и повторите короткий тон из шага 4 — снова должен прозвучать.
8. Получите настоящую тревогу warning/error (см. выше). Отправьте `{cmd:"speaker_tone", freqHz:440, durMs:10000}` — тон 10 с не обрезается. Пока он звучит, сразу остановите службу `ExchangeChecker` (или выключите / усыпите компьютер). Тон должен оборваться сразу; `ExchangeCheckerInpOut` не остаётся запущенной.
9. Если подменить файл драйвера другим (другой SHA-256) и перезапустить службу Exchange Checker: `{cmd:"speaker_status"}` возвращает `available=false`, `reason="blocked"`; тон не включается; `ExchangeCheckerInpOut` **не запускается**. Запасной путь трея — через колонки.
10. Если службу `ExchangeCheckerInpOut` удалить: `reason="not_installed"`, старт тона — ошибка «Системный динамик недоступен: драйвер не установлен.» Тон тогда должен прозвучать через колонки (запасной путь трея).
11. На не-amd64 или не-Windows (этого шага на Win7 x64 нет): `reason="unsupported_os"`.

Запишите для каждого шага «ОК» или что пошло не так. **Не присылайте** сам файл `.sys` в отчёте — достаточно хеша и снимка свойств службы.
